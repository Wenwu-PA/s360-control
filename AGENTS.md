# AGENTS.md — правила для кодинг-агента

## Проект
S360 Control: Linux-приложение для MSI MEG CoreLiquid S360 (CachyOS, Hyprland/Wayland). Python 3.12, PySide6.
- `s360_lcd.py` — ядро и CLI (протокол, ffmpeg, USB).
- `s360_gui.py` — GUI.
- `install.sh`, `uninstall.sh`, `packaging/` — установка.
- `docs/design/` — макеты GUI (цель редизайна), `docs/PLAN.md` — план работ, `docs/OPEN_QUESTIONS.md` — что неизвестно,
  `docs/PROTOCOL_VERIFIED.md` — что подтверждено захватами (источник истины для протокола).

## ЗАПРЕЩЕНО ТРОГАТЬ: протокол и запись на устройство
В `s360_lcd.py`: `cmd_report`, `data_reports`, `build_upload_plan`, `build_select_plan`, `build_direction_plan`,
`slot_for_direction`, `build_save_plan`, `build_brightness_plan`, `build_clock_plan`, `build_cooler_reports`,
`validate_curves`, `load_curves`, `DEFAULT_CURVES`, `PUMP_MIN_DUTY`, `COOLING_MODE_IDS`, `CHANNELS`, `do_send`, `cooler_mode_reports`, `feed_report`, `find_hidraw`, `_write_reports`, `cooling_set`,
`cooling_feed`, константы протокола (`VID`, `PID`, `SLOT_NAME`, `COOLING_MODES`, `REFERENCE_*`, `ENC`-параметры H.264).
Менять только если задача в PLAN.md прямо этого требует. Байты не «улучшать», тайминги не менять, ретраи не добавлять.
Новые команды устройства не добавлять. Если для функции нет данных протокола — оставить её недоступной (серый блок
с причиной) и записать вопрос в `docs/OPEN_QUESTIONS.md`. Не угадывать протокол.

## Железо: агент ничего не отправляет на устройство
НЕ запускать: `send`, `direction`, `cooling set --apply`, `cooling feed`, `systemctl --user start/enable s360-feed`,
не открывать pyusb/hidraw. Разрешено: `python3 -m py_compile ...`, `python3 s360_lcd.py selftest`, `plan`, `preview`,
`info`, `cooling status`. Реальные проверки на железе делает владелец.

## Как работать
- Одна задача из `docs/PLAN.md` за раз, по порядку. Ветка `feature/<задача>`, `main` не трогать, маленькие коммиты.
- Меняй минимум файлов. Всё, что работает сейчас (загрузка GIF, масштаб/поворот/фон, поворот экрана, режимы кулера,
  установка/удаление), должно продолжать работать.
- Проверка после задачи — только: `python3 -m py_compile s360_lcd.py s360_gui.py` и `python3 s360_lcd.py selftest`.
  GUI на сервере не запустить: в отчёте опиши, что владельцу посмотреть руками.
- Тесты: НЕ писать наборы тестов. Новую чистую логику (не GUI) — максимум одна проверка внутри `selftest()`.
  Никаких тестов внешнего вида, моков Qt, измерения покрытия.
- Не «валидировать всё подряд»: не перепроверять протокол, не гонять ffmpeg-свипы, не искать в интернете,
  не рефакторить то, что не просили, не переименовывать существующее.
- Лимит попыток: если проверка не проходит после 2 исправлений — остановись и опиши проблему. Не зацикливайся.
- Зависимости только PySide6, pyusb, ffmpeg. `install.sh`/`uninstall.sh` без задачи не менять.
- Отчёт после задачи (коротко): изменённые файлы; какие команды запущены и результат; что посмотреть владельцу;
  что осталось неизвестным.

## Стиль интерфейса
Русский язык. Честные статусы: никаких кнопок/иконок, создающих впечатление работающего управления; недоступное —
серое, с причиной. «Хост отправил» ≠ «экран принял»: подтверждения от устройства нет.
