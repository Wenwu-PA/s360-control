# Протокол S360: что подтверждено захватами (USBPcap, MSI Center, это устройство)

Захваты сняты на Windows, шина 1. **Важно:** в записях USBPcap описания устройств (VID:PID) сдвинуты относительно адресов.
Роль устройства определяется по трафику, а не по адресу/дескриптору:
- LCD (0db0:9ba6): Control SET_REPORT `21 09 01 02 00 00 40 00` + отчёт `01 6b 5a CMD …` (64 байта); данные — Interrupt OUT 1024 с ID 02. В записях это адрес 13.
- Кулер (0db0:6a05): Interrupt OUT 64 байта `d0 xx`, ответы Interrupt IN 64 байта `d0 xx`. Адрес 14.
- Адрес 12: пакеты `Ada…` по bulk (светодиоды Skydimo, не S360).
Нумерация записей — по списку заданий: 1 часы/GIF, 1-2 повторный Apply GIF, 2 страница Fan Setting, 3 Balance→Silent,
4 Silent→Game, 5 Game→Balance, 6 Customize Apply, 7 точка радиатора, 8 точка помпы, 9 яркость 100→50,
10 яркость 50→100, 11 Direction, 12 тумблер LCD, 13 режимы.

- Подтверждены применение стандартного режима часов MSI (стиль №1) и успешный возврат из часов к GIF.
- Подтверждено успешное воспроизведение GIF с параметрами 60 FPS и длительностью 8,95 секунды.
  Ранее воспроизводились файлы 20/3, 10 и 15 fps длительностью до ~2,5 с.

### Команды, подтверждённые захватами

Кадр команды: `01 6b 5a CMD 00 LEN(uint32LE) PARAMS`, всего 64 байта, нули в конце.

| Действие в MSI Center | Что уходит | Захват |
|---|---|---|
| Яркость N % | `cmd 18`, len 4, uint32LE N; затем «сохранение» (ниже). Видели 100, 50 | 9, 10 |
| Тумблер LCD Display выкл/вкл | то же, что яркость: выкл = 0, вкл = 100 | 12 |
| Direction | `cmd 1a`, len 4, uint32LE градусы (видели 180 и 0); сохранение; затем `cmd 50` + 8×`cmd 40` для текущего слота | 11 |
| Сохранение настроек | `cmd 20` (длина файла 3, имя `HMI_FW_Setting.ini`, len 22) → `cmd 22` (len 3) → отчёт ID2 с байтами `4d 53 49` («MSI») → `cmd 26` | 9-12 |
| System Clock | `cmd 36` len 12: `01 00 00 00`, `00 00 00 00`, **местное** время как unix-секунды (UTC+3 → +10800) → `cmd 50`: `05 00 05` + флаги, флаг стиля 1 = `01` | 1, 13 |
| Hardware Monitor | `cmd 50` params `00 05 0f 00 03 00 00 03 03 …` (смысл байтов не расшифрован; значения идут фоном через `cmd 30`) | 13 |
| Apply уже загруженного GIF | MSI **заново загружает файл целиком**: `cmd 50` + 8×`cmd 40` (слот 7) → `cmd 20/22` → данные → `cmd 26`. Файл MP4 был 664414 байт (650 отчётов), экран принял | 1-2 |

`cmd 50` params: `[режим][слайдшоу][число экранов][16 флагов]`. Режимы: 0 = Hardware Monitor, 1 = Video/Image, 5 = System Clock.
Флаги слотов изображения: индекс слота = номер слота (слот 7 → флаг №7). Режимы 2, 3, 4 (Banner, Weather, …) не видели.

Фоновые команды MSI Center: `cmd 30` (данные хоста, ~раз в секунду), `cmd 36` (часы, раз в минуту), `cmd 3a` (единицы температуры).

## Кулер

Отчёт 64 байта: `d0 40` (обороты %, 4 точки на вентилятор) и `d0 41` (температуры °C, 4 точки), затем **5 блоков по 8 байт**
со смещения 2 (смещения 2/10/18/26/34): `[режим][v1][v2][v3][v4][0][0][0]`. MSI шлёт пару 40→41 с паузой ~0.05 с,
при смене режима повторяет пару через ~0.4 с.

- Режимы: 0 = Silent, 1 = Balance, 2 = Game, 3 = Customize (захваты 3-6).
- Байты кривых при смене режимов 0/1/2 те же, что в Customize: меняется только байт режима.
- Блоки: 0 (`radiator1`) — вентилятор радиатора, 1–2 (`radiator2`, `radiator3`) — служебные,
  неиспользуемые каналы (в старых захватах обороты нулевые). MSI Center показывает один график радиатора.
  Блок 3 — вентилятор водоблока, 4 — помпа (сверено со скриншотами).
  GUI редактирует только блоки 0/3/4; служебные сохраняет и передаёт без изменений.
- Значения в захвате Customize (duty % / °C; это не прочитанные кривые готовых режимов): радиатор1 21,28,42,100 / 48,63,79,81; служебные блоки 1–2: 28,40,70,100 / 35,40,70,81;
  водоблок 13,23,35,53 / 51,64,75,81; помпа 60,60,89,100 / 59,68,75,81.
- Захват 7: перетаскивание первой точки радиатора поменяло только блок 0 (duty 21→2, temp 48→47). Захват 8: вторая точка помпы 60→72.
- Фоном: `d0 31` (опрос статуса) и `d0 85` (температура CPU хоста: uint16LE на смещениях 2/4) — как в старых захватах.
